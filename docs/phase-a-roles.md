# فاز A — معماری نقش‌ها (مربی / دانش‌آموز)

> وضعیت: **سند معماری** — هنوز پیاده‌سازی کامل حساب‌ها انجام نشده.  
> هدف: وقتی خواستیم عملی کنیم، از همین نقشه جلو برویم.

## ۱. هدف محصول

پویا فقط چت عمومی نباشد؛ پلی باشد بین:

| نقش | کار اصلی |
|-----|----------|
| **مربی / معلم** | ثبت‌نام → جزوه در مغز دوم → کلاس → آزمون → صدور **کد کلاس** |
| **دانش‌آموز** | ثبت‌نام → ورود با **کد مربی/کلاس** → دیدن درس و آزمون همان مربی |

محتوای پیش‌فرض پویا (مربیان داخلی اپ) برای همه باز می‌ماند مگر خلافش تصمیم بگیریم.

## ۲. تصمیم‌های قفل‌شده (پیشنهادی تا تأیید نهایی)

1. **نقش:** در پروفایل/ثبت‌نام یکی از `student` | `teacher` (فعلاً یک نقش فعال).
2. **کد:** در فاز اول **کد کلاس** (نه فقط کد مربی) — هر کلاس یک کد یکتا مثل `POUYA-7K3M`.
3. **عضویت:** دانش‌آموز می‌تواند چند کلاس داشته باشد.
4. **رسانه جزوه:** عکس + متن در فاز اول؛ PDF در فاز بعد.
5. **پول:** فاز A رایگان؛ اشتراک بعداً جدا طراحی شود.

## ۳. مدل داده (منطقی)

```
User
  id, role: student|teacher, displayName, createdAt

Classroom (کلاس)
  id, teacherId, title, grade?, joinCode, createdAt

Enrollment
  classroomId, studentId, joinedAt

Lesson (درس/جزوه)
  id, classroomId, title, body, attachments[], createdAt

QuizBank (آزمون مربی)
  id, classroomId, title, questions[]

ChatSession (تاریخچه — فعلاً محلی)
  id, userId?, title, messages[], updatedAt
```

## ۴. فازبندی اجرا

| فاز | تحویل | وابستگی |
|-----|--------|---------|
| **A0** | همین سند + تاریخچه گفتگوی محلی | بدون سرور |
| **A1** | نقش در پروفایل + UI انتخاب دانش‌آموز/مربی | local یا auth ساده |
| **A2** | ساخت کلاس + کد عضویت | DB مشترک |
| **A3** | جزوه مربی در مغز دومِ کلاس | A2 |
| **A4** | آزمون اختصاصی کلاس | A2 |
| **A5** | همگام‌سازی تاریخچه گفتگو با حساب | auth + DB |

## ۵. نگاشت به اپ فعلی

| بخش فعلی | نقش در فاز A |
|----------|----------------|
| تب حساب | انتخاب نقش، کد کلاس، لیست کلاس‌ها |
| تب مربی‌ها | مربیان داخلی پویا + «کلاس‌های من» |
| مغز دوم | جزوه‌های شخصی + (بعداً) جزوه کلاس |
| آزمون | آزمون عمومی + (بعداً) آزمون کلاس |
| گفتگو | تاریخچه محلی (A0) → بعداً ابری |
| API هوش مصنوعی | بدون تغییر نقش؛ فقط context کلاس اختیاری |

## ۶. امنیت و حریم (حداقلی)

- کد کلاس قابل حدس سخت نباشد (۸+ کاراکتر).
- دانش‌آموز فقط کلاس‌های enrolled را ببیند.
- مربی فقط کلاس خودش را ویرایش کند.
- تا قبل از auth واقعی، هیچ داده حساسی روی کلاینت منبع حقیقت نهایی نباشد.

## ۷. خارج از محدوده فاز A

- پرداخت و اشتراک
- نمره رسمی مدرسه / کارنامه
- ویدیو کنفرانس زنده
- نقش ادمین مدرسه

## ۸. قدم بعدی وقتی خواستیم عملی کنیم

1. انتخاب DB (مثلاً Postgres روی Liara یا Vercel).
2. جدول‌های `User` / `Classroom` / `Enrollment`.
3. UI تب حساب: نقش + ساخت/پیوستن کلاس.
4. اتصال مغز دوم به `Lesson` کلاس.
